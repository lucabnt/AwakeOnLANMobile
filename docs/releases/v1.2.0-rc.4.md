# v1.2.0-rc.4 - Reliable wake routing and Wi-Fi retries

A reliability and security update based on the 2026-11-15 technical review.

## Changes since RC3

- **One wake sender.** The Wake button, widget, Quick Settings tile and
  automations now share the same Android sender. When Wi-Fi is connected, the
  packet is sent on Wi-Fi even if mobile data or a VPN is the default network.
- **Wi-Fi rules retry when their window opens.** A rule triggered outside its
  allowed time window, or during its cooldown, is checked again when the window
  opens, as long as the phone is still on the same connection. Without
  exact-alarm access Android can delay this check.
- **Faster ping scans.** Ping uses ICMP sockets instead of starting a process per
  address, so a full `/22` fits within the 30-second limit. Kernels that deny
  ICMP sockets fall back to the previous method.
- **External integrations.** An intent with a wrong token now always receives
  `rejected`, even when the rule is paused. Apps using the correct token still
  see `disabled`.
- Devices saved in the same millisecond receive distinct identifiers.
- The app no longer rewrites the encrypted archive at every start.
- New [privacy notice](../../PRIVACY.md).
- Build and CI: patched `fast-xml-parser` (GHSA-474x-hrwr-fgx4), CI compiles the
  instrumented tests, and GitHub Actions are pinned to commit SHAs.

The archive format, backup format and MacroDroid contract are unchanged.
This remains an Android prerelease. Real-device and background-delivery
validation limits described in RC2 still apply.

## Wake routing verification

Multi-network behaviour has been tested on the emulator only and still needs
verification on physical hardware.

- Connect a phone to Wi-Fi without internet, keep mobile data enabled, and
  capture the packet on the target LAN.
- Repeat with a VPN active. Check both the configured destination and the
  default broadcast.
- Send from the device list, widget, tile and an automation. Verify the
  destination, UDP port and packet contents on the LAN for each.

## APK preparation - pending before publication

The draft intentionally has no APK attachments yet. Build from this release's
target commit on `main` with a clean working tree. The version is set to
`1.2.0-rc.4`, base versionCode `100203`.

1. In Android Studio, open the `android` project and use JDK 17 for Gradle.
2. Choose **Build > Generate Signed App Bundle / APK > APK**, select the existing
   maintainer keystore and build the **release** variant for all four ABIs.
3. Verify every APK with `apksigner verify --verbose --print-certs` and
   `zipalign -c -P 16 4`. Confirm embedded versionName `1.2.0-rc.4` and ABI codes
   ARMv7 `10020301`, ARM64 `10020302`, x86 `10020303`, x86_64 `10020304`.
4. After verifying the signature, name the distribution copies
   `awakeonlanmobile-<abi>-1.2.0-rc.4.apk`, using `armeabi-v7a`, `arm64-v8a`,
   `x86` and `x86_64`. Remove `-unsigned` only after checking the signature.
5. Generate `SHA256SUMS.txt` from the four final signed files and attach those
   five files to this draft.
6. Test updating an existing RC3 installation without uninstalling. Check Wake
   from the device list, widget and tile, and a Ping scan of the current subnet.
   Publish this draft as a **prerelease**, keeping stable/latest unchanged.

The expected maintainer certificate SHA-256 is
`b28b8a226b2e27771f5ba5a276ed16b5235c1b3d764a802bc68610e69e284fe9`.

The [RC3 APK preparation guide](v1.2.0-rc.3-apk-preparation.it.md) describes the
