# Preparazione APK per v1.2.0-rc.3

La release GitHub resta una bozza finche non sono pronti e verificati i quattro
APK firmati. La modifica inclusa centra il pulsante Use current Wi-Fi subnet,
lo avvicina al campo della subnet e gli applica uno stile secondario neutro.

## 1. Sorgenti e versione

Usare il commit indicato come target della bozza sul branch
`feature/wifi-discovery-diagnostics`. Prima della compilazione controllare che
non ci siano modifiche applicative non salvate. Se il branch e avanzato, usare
il commit esatto della bozza per mantenere corrispondenza tra sorgenti e APK.

La versione e gia impostata in package.json, package-lock.json e
android/app/build.gradle: **1.2.0-rc.3**, base versionCode **100202**.
Non occorre modificarla ulteriormente.

| ABI | versionCode | Nome finale |
| --- | --- | --- |
| armeabi-v7a | 10020201 | awakeonlanmobile-armeabi-v7a-1.2.0-rc.3.apk |
| arm64-v8a | 10020202 | awakeonlanmobile-arm64-v8a-1.2.0-rc.3.apk |
| x86 | 10020203 | awakeonlanmobile-x86-1.2.0-rc.3.apk |
| x86_64 | 10020204 | awakeonlanmobile-x86_64-1.2.0-rc.3.apk |

I quattro codici sono superiori ai corrispondenti della RC2. Rinominare un APK
RC2 non ne modifica la versione interna e non produce una RC3.

## 2. Generazione e firma in Android Studio

1. Aprire il progetto `android` in Android Studio. Usare **JDK 17** per Gradle;
   il progetto utilizza Android SDK 35 e NDK 27.1.12297006.
2. Eseguire **Build > Generate Signed App Bundle / APK > APK**.
3. Selezionare lo **stesso keystore e alias delle release precedenti**, quindi
   inserire le credenziali nella finestra di Android Studio. Non creare una nuova
   chiave e non condividere chiave o password nella chat o nel repository.
4. Scegliere **release** e generare tutte e quattro le architetture.
5. Attendere **BUILD SUCCESSFUL**. Usare Locate dalla notifica per individuare
   gli APK: con la procedura gia usata si trovano in `android/app/release/`.
   Il comando assembleRelease senza firma configurata produce invece APK unsigned
   in `android/app/build/outputs/apk/release/`; non allegarli alla release.

Non eseguire contemporaneamente altre build sullo stesso progetto: su Windows
un file DEX occupato puo impedire il completamento della build.

## 3. Verifiche dei quattro APK

Gli strumenti seguenti si trovano nella cartella Android SDK build-tools/35.0.0.
Per ciascun APK eseguire, sostituendo il percorso tra virgolette:

```powershell
apksigner.bat verify --verbose --print-certs "percorso.apk"
aapt.exe dump badging "percorso.apk"
zipalign.exe -c -P 16 4 "percorso.apk"
```

Usare i percorsi completi degli strumenti se non sono nel PATH.
Verificare firma valida, versione 1.2.0-rc.3, codice ABI della tabella,
applicationId `com.awakeonlanmobile` e allineamento a 16 KiB.
Il digest SHA-256 del certificato deve essere:

```text
b28b8a226b2e27771f5ba5a276ed16b5235c1b3d764a802bc68610e69e284fe9
```

Il nome generato puo contenere `-unsigned.apk` anche quando Android Studio ha
firmato il file: fa fede la verifica con apksigner. Solo dopo il controllo,
copiare gli APK in `release-artifacts/1.2.0-rc.3/signed/` con i nomi della tabella,
rimuovendo il suffisso `-unsigned`. Non sovrascrivere i file della RC2.

## 4. Checksum e prova sul telefono

Dalla cartella contenente soltanto i quattro APK firmati finali:

```powershell
$checksumLines = Get-ChildItem -File -Filter '*.apk' | Sort-Object Name | ForEach-Object {
    $apkHash = Get-FileHash -LiteralPath $_.FullName -Algorithm SHA256
    '{0}  {1}' -f $apkHash.Hash.ToLowerInvariant(), $_.Name
}
$checksumLines | Set-Content -LiteralPath 'SHA256SUMS.txt' -Encoding ascii
```

Provare l'aggiornamento sopra RC2 senza disinstallare: dispositivi e automazioni
salvati devono restare disponibili. In Scan Hosts verificare entrambi i temi,
centratura e leggibilita del pulsante, rilevamento subnet, inserimento manuale
e avvio/annullamento della scansione. Con font ingranditi il testo deve poter
andare a capo senza uscire dal pulsante.

## 5. Allegati della bozza

Caricare i **quattro APK firmati con i nomi finali** e **SHA256SUMS.txt** nella
bozza v1.2.0-rc.3. Confrontare nomi e checksum con i file locali. Conservare
**Set as a pre-release**; non selezionare la release stabile/latest.
Questa richiesta prepara la bozza e le istruzioni: la pubblicazione resta da fare
quando firma, allegati e prova di aggiornamento sono completati.
