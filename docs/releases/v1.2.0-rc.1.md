# v1.2.0-rc.1 — Scheduled wakes and external events

Release candidate prepared on 2 November 2026. This is not yet a stable, hardware-validated release.

- **Automation** replaces the Add Device tab. A floating **+** at the bottom right of Device List opens the device form; adding a device during rule creation returns to the draft.
- Automation setup follows **Device → When → Review**, with compact weekday choices, optional advanced settings, readable rule cards and an in-app **How to use** guide. Rule and global pause switches have separate explanations; connection, test and delete actions live under **More**.
- Creating an enabled rule or turning a rule on also resumes the main Automatic wakes switch. Renaming an already-enabled rule preserves a deliberate global pause. Enabling a rule can resume other enabled rules; the review screen makes that explicit.
- Create one-time, weekly or authenticated external-event rules, with enable switches, local history, cooldown, permitted days/time windows, optional result notifications and a real-send test action.
- Native AlarmManager schedules support exact/flexible modes, visible permission suspension, late-delivery skips, boot/timezone restoration and persistent occurrence claims.
- MacroDroid is the first selected provider. A real MacroDroid 6.0.11 macro passed end-to-end validation on Android 15 / API 35, including dynamic IDs, duplicates, global pause and token revocation/reconnection. The guide includes the tested setup; physical-phone and prolonged-background checks remain open.
- The device row now has a quiet reachability indicator, with bounded/cancellable TCP or ICMP checks on entry and after an in-app wake.
- Encrypted v2 backups include rules with remapped device IDs. Imported rules stay disabled; tokens/history/permissions are excluded. Device-only backups remain readable.

Read the [automation guide](../automation.md) for permissions, external-event credentials, delivery limits and backup compatibility. Read the [validation record](../automation-validation.it.md) for performed tests and remaining release gates.

Wi-Fi triggers/SSID filters, automatic discovery, changed-IP recovery and advanced diagnostics are planned for the second release. iOS remains an unsupported upstream scaffold for these features.

Automations can submit packets while locked only after explicit activation and the first unlock after boot. Exact-alarm access and network availability are required where applicable. Doze/vendor policies may delay delivery; force-stop prevents delivery until reopening. A submitted WOL packet does not prove startup. A crash around UDP submission may leave an uncertain result; automatic replay is avoided.

Candidate version: `1.2.0-rc.1`; base Android versionCode: `100200`; split codes: `10020001`–`10020004`. Release outputs are unsigned unless the maintainer provides the existing signing configuration. Do not publish stable or replace any existing tag until the hardware/provider gates are complete.
